# هم‌مسیر (HamMasir) — نمونه اولیه‌ی حمل مرسوله هم‌مسیر

اپلیکیشن موبایل فارسی/RTL با Expo SDK 57 و Expo Router. این مخزن فقط فرانت‌اند است؛ پروژه‌ی ASP.NET Core در آن وجود ندارد. ورود با OTP، ثبت کاربر، پروفایل و برنامه‌های سفر طبق `swagger_final.pdf` به بک‌اند واقعی متصل‌اند. سفارش‌ها، پیشنهادها، تحویل‌ها، تنظیمات انحراف و پشتیبانی چون در این مستند وجود ندارند، همچنان mock حافظه‌ای هستند.

## راه‌اندازی

```bash
npm install
cp .env.example .env   # سپس مقادیر را متناسب با محیط خود تنظیم کنید
npx expo start
```

### متغیرهای محیطی

| متغیر | توضیح |
| --- | --- |
| `EXPO_PUBLIC_API_BASE_URL` | آدرس سرویس HamMasir (پیش‌فرض: `https://localhost:7220`). برای دستگاه واقعی باید آدرس LAN ماشین توسعه را وارد کنید. |
| `EXPO_PUBLIC_API_TIMEOUT_MS` | مهلت درخواست‌ها (پیش‌فرض: `20000`) |
| `GOOGLE_MAPS_API_KEY` | کلید Google Maps برای اندروید (بدون آن نقشه در اندروید بدون کاشی نمایش داده می‌شود؛ iOS به‌صورت پیش‌فرض از Apple Maps استفاده می‌کند) |
| `GOOGLE_MAPS_IOS_API_KEY` | کلید Google Maps برای iOS (اختیاری) |

برای APK تستی مستقل، پس از ورود به حساب Expo و پیکربندی پروژه:

```bash
npx eas-cli@latest build --platform android --profile preview
```

## ساختار پروژه

```
src/
├── api/            # لایه ارتباط با بک‌اند (client، endpointها، تایپ‌ها، قرارداد قابلیت‌های مفقود)
├── components/ride/# کامپوننت‌های رابط کاربری سفر (bottom sheet، دکمه، کارت گزینه سفر، …)
├── constants/      # پالت رنگ و توکن‌های رابط سفر + نگاشت transportType
├── features/       # auth (نشست و توکن) و trip (مبدأ/مقصد/انتخاب قطعه سفر)
├── utils/          # قالب‌بندی فارسی، تاریخ شمسی، اعداد فارسی
└── app/
    ├── (auth)/     # ورود با کد یک‌بارمصرف (OTP)
    ├── (ride)/     # تجربه مسافر: home، journeys، account، search، trip، plan-editor، settings
    └── (dashboard)/# داشبورد، ارسال بسته، برنامه و پروفایل
```

## وضعیت فعلی API

فقط ۱۱ عملیات زیر از مستند به `apiRequest` و بک‌اند متصل شده‌اند. آدرس پیش‌فرض بنا به تنظیم این پروژه `https://localhost:7220` است. خطاهای این سرویس‌ها به mock برنمی‌گردند. توکن Bearer در موبایل با SecureStore و در وب با localStorage نگه‌داری می‌شود؛ برنامه دیگر با توکن نمایشی وارد نمی‌شود. فرم OTP شش‌رقمی است و کد توسعه، فقط اگر خود سرویس برگرداند، نشان داده می‌شود.

برای تست روی همان سیستم بک‌اند، سرور را روی این آدرس اجرا کنید و گواهی HTTPS توسعه را معتبر کنید. برای وب، بک‌اند باید CORS مبدأ Expo را مجاز کند. روی گوشی فیزیکی `localhost` به خود گوشی اشاره دارد؛ در آن حالت `EXPO_PUBLIC_API_BASE_URL` را به آدرس قابل‌دسترسی سیستم بک‌اند تغییر دهید.

| متد | مسیر | کاربرد |
| --- | --- | --- |
| `POST` | `/api/auth/request-code` | ارسال کد تایید |
| `POST` | `/api/auth/verify-code` | تایید کد و دریافت توکن |
| `POST` | `/api/Users/Login` | ثبت کاربر با نام کامل |
| `GET` | `/api/users/me/profile` | خواندن پروفایل |
| `PUT` | `/api/users/me/profile` | ویرایش پروفایل |
| `GET` | `/api/travel-plans` | فهرست مسیرهای ذخیره‌شده (سفرهای من) |
| `GET` | `/api/travel-plans/{id}` | جزئیات یک مسیر |
| `POST` | `/api/travel-plans` | ذخیره مسیر جدید |
| `PUT` | `/api/travel-plans/{id}` | ویرایش مسیر |
| `DELETE` | `/api/travel-plans/{id}` | حذف مسیر |
| `PATCH` | `/api/travel-plans/{id}/status` | فعال/غیرفعال کردن مسیر |

ساعت برنامه با قالب `HH:mm:ss` (نوع `TimeOnly`) ارسال می‌شود؛ نمونه‌ی ساعت دارای `Z` در خود PDF خطای ۴۰۰ گرفته است. اگر پاسخ موفق ویرایش یا تغییر وضعیت بدنه نداشته باشد، برنامه جزئیات مسیر را دوباره با GET دریافت می‌کند.

عملیات زیر در مستند نیستند و فقط به mock متصل‌اند؛ هیچ درخواست واقعی برایشان ارسال نمی‌شود:

| متد | مسیر پیشنهادی mock | کاربرد |
| --- | --- | --- |
| `GET` | `/api/orders/mine` | فهرست mock سفارش‌های ثبت‌شده |
| `POST` | `/api/orders` | ثبت mock سفارش مرسوله |
| `POST` | `/api/matches/{id}/accept` | پذیرش mock پیشنهاد |
| `GET` / `PUT` | `/api/users/me/detour-preferences` | تنظیم mock حدود جست‌وجو و انحراف |
| `GET` | `/api/deliveries/mine` | تحویل‌های mock |
| `GET` / `POST` | `/api/support/tickets/mine` و `/api/support/tickets` | پشتیبانی mock |

## محدودیت‌های مهم

- تطبیق مسیر، مسافت و زمان واقعی پیاده‌روی/حمل‌ونقل عمومی در این نسخه پیاده‌سازی نشده است. مقادیر پیشنهادهای داشبورد داده‌ی نمونه‌اند.
- Push، زمان‌بندی اعلان، کد یک‌بارمصرف دریافت/تحویل، پرداخت و تسویه وجود ندارند. صفحه‌ی اعلان و تحویل این محدودیت را اعلام می‌کنند و کد نمونه‌ی قابل سوءاستفاده نمایش نمی‌دهند.
- ثبت سفارش و تنظیمات انحراف فقط تا وقتی برنامه اجراست در حافظه می‌مانند؛ برای سفارش واقعی از آن‌ها استفاده نکنید.
- صفحه‌ی انتخاب مکان در موبایل از قابلیت geocoding دستگاه استفاده می‌کند و جایگزین سرویس نقشه/مسیریابی تجاری یا داده‌ی معتبر مترو و اتوبوس تهران نیست.
- استثناهای تاریخ‌دار برای برنامه‌ی هفتگی، احراز هویت مدارک و فرایند تحویل سمت سرور در این مستند وجود ندارند.

قابلیت‌های غایب در `src/api/capabilities.ts` مستند شده‌اند. APIهای دیگر فقط پس از ارائه‌ی قرارداد بک‌اند به سرویس واقعی متصل می‌شوند.
